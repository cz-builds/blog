## 0. 一页纸版本

**发生了什么**：写完方法论之后，我试着让 AI 讲、我一步一步读和看。实际感受是：能学到的东西有限，而且知识框架不稳，概念记住了几个，连不起来，过几天就散了。

**诊断**：问题不在讲得好不好，而在信道本身。“AI 讲、我读”是一条**单向、线性、无状态、没有校验、没有刷新**的信道。它把一张图压成一条文字流发过来，指望我用 4 个槽的工作记忆把图重建出来。丢包是必然的，最先丢的是概念之间的连接，而框架恰恰就是这些连接。

**设计**：把它当成一个通信工程问题，设计了一套知识传输协议 KTP，做成了一个工具，叫**外脑链路**：

1. **编码器**：把一份资料（论文、数据手册、教材、整个代码项目）或一个主题，编码成一张目标知识图谱。图谱分两层：**核心层**是必须进脑子的 12–24 个概念和它们之间的类型化关系；**索引层**是不用背、但要知道去哪查的细节，每条都带出处。
2. **协议**：握手（测出你已经有什么，只发差量）→ 骨架（先装模块和主干）→ 数据包（猜 → 读 → 合上复述 → 诊断校验）→ 失败就换一种讲法重传 → 连接校验 → 凭记忆重建整张图 → 按遗忘曲线刷新。
3. **链路指标**：同步率（分概念和连接两项）、误码率、高置信错误、待刷新数量。全部来自闭卷数据。

**关于“无损”**：一次性的单向传输做不到无损。人脑只在加工时写入，写进去之后还会漏电。能做到的是**可验证的无损**：核心层的每个节点、每条连接，你都能闭卷重建，并且有刷新机制维持；不进脑子的细节，全部有带出处的索引。什么都不会悄悄丢掉：要么在你脑子里且被验证过，要么在索引里且你知道去哪找。

## 1. 为什么“AI 讲、我读”会丢包

把这次失败拆开，有五个丢包点。

### 1.1 被动通道

Chi 和 Wylie 的 ICAP 框架把学习活动分成四级：被动（Passive）< 主动（Active）< 建构（Constructive）< 交互（Interactive），级别越高学得越多（Chi & Wylie, 2014）。读 AI 的讲解，哪怕读得很认真，也只是被动这一级。上一篇已经说过“被动看 AI 讲解 ≈ 重读”，可是方法论只是一组规则，执行要靠我自己。真坐下来学的时候，阻力最小的路径永远是“再让它讲一遍”。

### 1.2 串行化损失

知识框架是一张图：节点是概念，边是关系。一段讲解是一条线性文字流，相当于把图做了一次深度优先遍历再串行化发出来。边信息大部分被丢掉了，剩下的散落在相隔很远的段落里。

接收方要做反串行化：一边读，一边在脑子里把图重建出来。可工作记忆大约只有 4 个组块（Cowan, 2001）。节点还勉强装得下，节点之间的连接很快就溢出了。结果就是**记住了几个概念，但它们悬在半空中**，也就是我感受到的“框架不稳”。

### 1.3 发送方没有接收方的模型

Ausubel 有一句很有名的话：如果要把整个教育心理学归结为一条原则，那就是**影响学习最重要的单一因素是学习者已经知道什么，先弄清楚这一点，再据此去教**（Ausubel, 1968）。

聊天里的 AI 并不维护“你已经知道什么”的持久模型。于是它会重复发送你已经有的东西（浪费带宽），也会跳过你缺的前置（接收端出现悬空指针）。

### 1.4 没有 ACK，也没有校验

“我懂了”的感觉不是 ACK。人普遍高估自己对事物的理解程度，直到被要求一步一步解释时才发现说不清，这叫解释深度错觉（Rozenblit & Keil, 2002）。AI 的讲解越流畅，这种错觉就越强。

没有校验，误解就会无声地写进去。就像一条没有 CRC 的链路，出了误码也没人知道。

### 1.5 没有刷新

写进去的东西会衰减。没有刷新控制器，几天后框架就散了。

### 1.6 可选的互动会被跳过

还有一个证据值得单独说。Oreopoulos 和 Low 在田纳西州 18 所中学做了两年的随机实验：Khanmigo 被设置成只引导、不给答案，结果数学成绩只提高了约 0.06–0.08 个标准差，和不带 AI 的普通 Khan Academy 练习差不多。原因是学生很少真正用它对话：中位数学生只在三分之一的练习日里给它发过消息，做错题的练习中只有 17% 去问了它，发出的消息大多是直接报答案，或者点一下推荐提示（Oreopoulos & Low, 2026）。

**教训：互动如果是可选的，就会被跳过。闭环必须是协议的一部分，不能是一个可以不按的按钮。**

## 2. 信道规格书：人脑这一端

设计链路之前，先读接收端的数据手册。

| 参数 | 典型值 | 设计含义 |
|---|---|---|
| 意识层面的信息吞吐 | 约 10 bit/s（Zheng & Meister, 2025） | 不能靠加大输入提速，只能提高每个比特的有效性 |
| 工作记忆容量 | 约 4 个组块（Cowan, 2001） | 每个数据包的新元素不超过 4 个 |
| 写入条件 | 只在加工时写入：提取、生成、解释 | ACK 必须是生成式的，“看懂了”不算 |
| 存储格式 | 图式：新信息相对已有知识编码 | 每个新节点必须挂到一个已验证的节点上 |
| 保持特性 | 会衰减；间隔提取能让衰减变慢 | 需要刷新控制器，刷新间隔逐次拉长 |
| 高交互材料 | 新手先分开学元素、再学元素间的交互效果更好（Pollock et al., 2002） | 先传节点，再单独校验连接 |

### 2.1 你说的“词嵌入空间”是对的

在语言模型里，一个词的意义就是它相对于其他词的位置。人脑里也类似：说你“懂了”一个概念，意思是它和足够多的已知概念以正确的关系连在一起。

这带来两个直接的设计推论：

1. **传输的基本单位是边，不是节点。** 孤立的节点会被回收。所以协议规定，没有挂载点的概念不发；节点同步之后，还要单独校验连接。
2. **一个概念最好由它的最近邻来界定。** 嵌入空间里，一个点的意义取决于它和邻居在哪些维度上不同。教学上对应的是对比学习：把容易混淆的邻近概念放在一起比较。案例比较的元分析给出的平均效应约为 d = 0.50（Alfieri et al., 2013）。所以每个数据包都有一栏“边界”，专门讲它和最近邻的区别。

### 2.2 压缩靠的是共享码本

信息论里，如果收发双方共享一部分码本 Y，发送 X 只需要传条件熵 H(X|Y)。对应到学习：

- **握手**就是测量接收方已有的码本，然后像 rsync 一样只传差量：你已经会的，只发一道校验题；不会的，才发完整数据包。
- **挂载**就是用接收方已有的码本编码。给一个 IC 专业的人讲 KV Cache，最省带宽的说法是“用 BRAM 存中间结果，避免重复计算”。这一句话借用了你脑子里现成的一整块结构。

## 3. 重新定义“无损、正确、高效”

| 目标 | 可检验的定义 | 协议里的机制 |
|---|---|---|
| **无损** | 目标图谱里的每个节点和每条边：闭卷能重建（回忆，不是再认）；隔一段时间仍然成立。不进脑子的细节都在索引层，带出处 | 闭卷复述、诊断校验、连接校验、凭记忆重建、刷新；索引层 |
| **正确** | 误解被显式探测和纠正；资料模式下的事实以原文为准 | 诊断题的每个错误选项对应一个真实误解；信心评级标出高置信错误；数据包引用原文位置 |
| **高效** | 单位时间内被验证的元素数最大化 | 只发差量；骨架先行；包大小匹配工作记忆；按误码率调节速率 |

“骨架先行”可以用图片加载来理解。线性讲解像逐行扫描的 JPEG：顶部几行已经清清楚楚，可你直到最后都不知道整张图是什么。外脑链路像渐进式 JPEG：第一遍先给出整张图的低分辨率版本（模块和主干），之后每一遍都在补细节，每个细节落下来时都已经有位置可放。这和 Ausubel 的“先行组织者”是同一个思路。

## 4. 产品：外脑链路

### 4.1 为什么是这个形态

考虑过的几种形态，都不够：

| 形态 | 为什么不够 |
|---|---|
| 更好的讲解、视频、动画 | 还是被动通道 |
| 更长、更有引导的对话（包括各家的学习模式） | 线性、没有持久的接收方模型，互动是可选的 |
| Anki 之类的卡片 | 只有节点，没有结构；卡片还得自己做 |
| 概念图工具 | 有结构，但没有校验，也没有刷新 |

最后的选择是：**一张持久、共享、可见的图谱 + 强制闭环的协议 + 跨会话的接收方模型**。图谱需要二维空间，所以做成网页，而不是聊天流。它在 Claude 里以 Artifact 的形式运行：生成和批改调用 Claude，进度存在你自己的账户里。

### 4.2 架构

```
资料（PDF / EPUB / DOCX / Markdown / 源代码 / ZIP）或一个主题
   │  源适配器：按页、按文件、按章节切片，保留位置标记 [[p.12]] [[rtl/uart_tx.v]]
   ▼
编码器（Claude）
   · 小材料：一次直接构建
   · 大材料：逐段提取候选概念（map）→ 由最强模型合并成图（reduce）
   · 本地检索：为每个概念从原文里找证据段落
   ▼
目标图谱 TX
   · 核心层：12–24 个概念、类型化关系、主干
   · 索引层：不用背的细节，每条带出处
   │
   ▼  KTP 协议
你的长期记忆 RX：每个概念、每条连接各有一条遗忘曲线
   │
   ▼
链路指标：同步率（概念 / 连接）、误码率、高置信错误、待刷新、额度
```

### 4.3 协议栈

借用分层网络协议的结构，每一层都对应一个具体机制和它的证据：

| 层 | 类比 | 机制 | 依据 |
|---|---|---|---|
| 应用层 | 业务需求 | 学习目标决定图谱裁剪：什么进核心层，什么进索引层 | 直接性原则（上一篇） |
| 图层 | 路由 | 按拓扑序传输，前置全部同步之后才发下一个；没有挂载点的节点不发；骨架先行 | Ausubel 先行组织者；知识空间理论的“外缘”（Doignon & Falmagne, 1985） |
| 链路层 | ACK / CRC / 重传 / 流控 | 每包不超过 4 个新元素；ACK = 合上内容后用自己的话复述；CRC = 每个错误选项对应一个误解的诊断题，外加信心评级；NAK 后换一种表征重传；新包额度按误码率调节：误码率高于 40% 减半，低于 15% 且用满额度时加 1（类似 TCP 的 AIMD） | 自我解释（g ≈ 0.55，Bisra et al., 2018）；超纠正效应（Butterfield & Metcalfe, 2001） |
| 物理层 | 编码方式 | 文字配图谱（双重编码）；先具体后抽象；类比来自你的领域 | 上一篇第 3 节 |
| 刷新控制器 | DRAM 刷新 | 遗忘曲线 R(t) = (1 + t/9S)⁻¹（FSRS v4 的形式）；R 跌破 90% 时安排提取；成功放大稳定期 S，复习时 R 越低放大越多；失败把 S 缩到 30% | 间隔效应（Cepeda et al., 2008） |
| 擦洗 | 内存 scrub | 隐藏所有连线，凭记忆把概念连起来，再和目标图谱逐条对照 | 凭记忆画概念图和闭卷复述一样有效，对着材料画图则明显不如闭卷提取（Karpicke & Blunt, 2011；Blunt & Karpicke, 2014）；自己构建概念图 g = 0.72，看现成的图 g = 0.43（Schroeder et al., 2018） |

记忆和 DRAM 很像：写进去之后会漏电，需要刷新。区别在于，每次成功刷新都会让下一次刷新的间隔变长。

### 4.4 一个数据包长什么样

以内置示例里的 KV Cache 为例：

| 字段 | 内容 | 作用 |
|---|---|---|
| 预测 | 如果每生成一个 token 都把前面所有 token 的 K、V 重算一遍，总计算量随长度怎么增长？（线性 / 平方 / 不变） | 先猜后学，激活好奇心 |
| 挂载 | 就是用存储换计算的缓存，和 CPU cache、或者你在 FPGA 里用 BRAM 存中间结果，是同一个思路 | 用你已有的码本编码 |
| 核心 | 过去 token 的 K、V 不会再变，算出来就存起来；新 token 只算一份 Q、K、V，再和缓存做注意力 | 是什么，为什么需要它 |
| 边界 | 只存 K、V，不存 Q；它省的是计算，不是访存，每步反而要多读一遍整个缓存 | 和最近邻的区别、最常见的误解 |
| 实例 | Llama-2-7B 每个 token 的 KV Cache = 2 × 32 × 4096 × 2 字节 = 0.5 MiB；4K 上下文、batch=8 就是 16 GiB，超过权重本身 | 带数字的具体实例 |
| ACK | 合上内容：KV Cache 存的是什么？省掉了什么，代价是什么？ | 闭卷生成，AI 按要点批改 |
| CRC | 4 选 1，其中一个错误选项是“它减少了每步要从显存读取的数据量” | 专门探测“省计算 = 省访存”这个误解 |
| 重传 | 换个角度：给前文每一句做好卡片，K 是索引，V 是内容…… | 第一次没过时换表征 |

### 4.5 可扩展性：任何资料都能编码

这是这个工具和普通“AI 讲解”的根本区别：**它不是讲一个主题，而是把一份资料编码成图谱再传输**。扩展性来自三个设计：

**1. 源适配器。** PDF 按页切片（位置标记是页码），代码项目按文件切片（标记是路径，自动跳过 node_modules、构建产物和二进制文件），DOCX 和 EPUB 按章节切片，Markdown 和 TXT 按标题切片。位置标记会一路保留到数据包里，所以每个说法都能回到原文核对。

**2. 按资料类型定义“核心”。** 同样是 30 页，论文、数据手册和代码的骨架完全不同。编码器对每种资料使用不同的核心概念标准：

| 资料 | 核心层 | 索引层 |
|---|---|---|
| 论文 | 要解决的问题、已有方法的局限、关键想法、方法组成、关键假设、证据、局限，以及读懂它必需的前置知识（标为背景节点） | 实验细节、超参数、具体数值 |
| 数据手册 | 功能框图里的模块、接口与引脚分组、工作模式与状态转换、配置流程、时序约束、关键参数的含义 | 具体数值、逐位寄存器定义（带页码） |
| 代码项目 | 架构与分层、核心数据结构、一份数据从进到出的路径、关键模块的接口、状态机与关键算法、构建和运行方式、设计取舍 | 函数签名、配置项、文件位置 |
| 教材 | 各章的大概念、贯穿全书的主线、方法及其适用条件、推导关系 | 公式细节、例题，留给展开后的子图谱 |

**3. 分形展开。** 一本 500 页的教材塞不进一张 20 个概念的图。所以图谱可以分层：先同步顶层框架，再把任意一个模块“展开”成一张独立的子图谱，子图谱只使用原文中和这个模块相关的部分。大材料的编码走 map-reduce：先逐段提取候选概念，再合并成一张图，最后在本地为每个概念检索原文证据。教材、大型代码库都按这个流程处理：顶层框架同步完，再一个模块一个模块往下展开。

## 5. 链路指标：只认闭卷数据

| 参数 | 符号 | 定义 | 目标 |
|---|---|---|---|
| 同步率 | SYNC | 概念同步与连接同步的平均 | ≥ 85% |
| 概念同步 | SYNC_N | 所有概念当前保持率 R 的平均，没同步的记 0 | |
| 连接同步 | SYNC_E | 所有连接当前保持率的平均。**框架稳不稳，主要看这一项** | |
| 误码率 | BER | 最近 20 次校验中失败的比例 | 10%–20% |
| 高置信错误 | HCE | 选了“确定”却答错的次数，最危险的一类误解 | 0 |
| 待刷新 | DUE | 保持率已经跌破 90% 的元素数 | 0 |
| 新包额度 | CRED | 每次同步最多发几个新数据包，按误码率自动调节 | 2–10 |
| 7 天后同步率 | SYNC@7d | 如果一周不复习，同步率会掉到多少 | |

误码率的目标不是 0。上一篇说过，练习正确率在 70%–85% 时学得最好；一直不出错，说明难度太低，或者校验太松。

同步率最直观的用处，是把“框架不稳”变成一个能看到的数字。示例主题跑完第一轮（6 个新概念、几道连接校验、一次凭记忆重建）之后，一个典型的读数是：概念同步 47%，连接同步 17%。概念记住了一半，连接只接上了不到五分之一。“记住了几个概念、但连不起来”这种感受，从此有了刻度。

## 6. 怎么用

**一次同步，约 20 分钟：**

1. 先刷新到期的元素（最多 4 个连续刷新，之后穿插进行）；
2. 在额度内传输新概念（默认 6 个），每个都走一遍“猜 → 读 → 合 → 验”；
3. 两端都同步之后，插入连接校验；
4. 结束前做一次凭记忆重建；
5. 结束时，额度按本次误码率自动调整。

**一周的节奏：** 每天一次同步，主要时间花在刷新和新包上；每周做一次完整的凭记忆重建；大材料先同步顶层，再每周展开一到两个模块。

**换成自己的资料：** 在工具里选“换成我的资料”，拖进 PDF、整个代码文件夹或 ZIP，写清楚学习目标（越具体，图谱越准）和你的背景（用来挑类比和判断前置），选好资料类型和图谱规模，生成即可。生成过程在页面里能看到每一步。

**不能调用 AI 时：** 可以在工具里复制“生成提示词”，在任意 Claude 对话里贴上材料生成知识包 JSON，再导入进来。

---

## 7. 怎么知道它真的更好

这套设计本身也是一组假设，需要在自己身上验证。实验可以这样做：

1. 选两个难度相近、都不熟的主题；
2. 一个用旧方式（AI 讲、我读，加上上一篇的方法论规则），一个用外脑链路，投入的时间相同；
3. 7 天后做同一种闭卷测试：一张白纸，把框架画出来，按目标图谱算连接召回率；再做 5 道换了情境的迁移题；
4. 顺便检查校准：工具显示的同步率，和白纸测试的结果对得上吗？

## 8. 局限

- **图谱质量取决于编码器。** AI 可能漏掉重要概念，也可能连错关系。资料模式下每个节点都有出处可查；主题模式没有原文可对，重要领域请拿教材目录或课程大纲对照一遍。
- **批改有误差。** AI 按要点批改闭卷复述，偶尔会过松或过严；诊断题也可能被猜中，所以加了信心评级、换情境的第二道题，以及“猜的”不算完全同步。
- **遗忘模型是简化版。** 参数没有针对个人拟合，同步率是估计值，不是测量值。白纸测试才是金标准。
- **它负责“框架”这一层。** 会做（程序性技能）还得靠真实任务的练习和反馈，也就是上一篇里的“实战”。外脑链路让你在动手之前有一张稳固的地图。
- **工程限制。** 扫描版 PDF 没有文字层，要先 OCR；页面不能联网抓取网页内容，资料需要上传或粘贴；离开 Claude 运行时不能生成新图谱。

## 附：在普通对话里用这套协议

不方便打开工具的时候，可以把下面这段放进 Claude 对话，让它按 KTP 的节奏跑：

```
你是我的知识链路控制器。目标：把【主题或我贴的资料】的知识框架同步进我的长期记忆。按下面的协议执行：
1. 握手：先列出 12–18 个核心概念（分 3–5 个模块，标出前置关系），让我标出已经会的；会的只出一道校验题。
2. 一次只发一个数据包，按前置顺序：先问一个预测题 → 给出挂载（用我的背景【IC/FPGA】类比，并说明类比在哪里不成立）、核心、边界（和最容易混淆的概念的区别）、实例 → 让我闭卷复述 → 出一道 4 选 1 诊断题（每个错误选项对应一个真实误解），我会附上信心（确定/大概/猜的）。
3. 我答错时，先说明我的误解错在哪，再换一种表征重讲，然后换情境再考一次。
4. 每同步 3 个概念，出一道必须同时用到两个概念的连接题。
5. 每 6 个新概念后停下，让我凭记忆列出所有概念及它们之间的关系，你逐条对照，指出漏掉和连错的。
6. 维护一张状态表（概念 | 状态 | 错过的误解），每次回复末尾更新。不要一次讲太多，不要在我作答前给答案。
```
